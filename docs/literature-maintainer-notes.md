# Implementation notes

The everyday controls are in [the short guide](literature-quickstart.md). This file records the few technical choices needed for maintenance.

- `core/literature_discovery.py`: configuration validation, provider adapters, deterministic phrase rules, identity checks, curator transitions. `discover_literature` manages bounded requests, reports and checkpoints. `core/discovery_models.py` and migration `0011` store the private inbox, identifiers, evidence, decisions and runs. No public route or scientific-measurement model was added.
- The local management command uses Django's selected **default** connection and application service account. It does not call the anonymous publication-suggestion API, which lacks discovery provenance and durable rejection identity. Keep the service and `.env` readable only by trusted operators. Admin requires staff membership and model permissions; accepting also requires add-Reference permission. Publication approval remains a separate Reference permission/workflow. No new credentials or worker dependency is needed.
- Public suggestions continue using `POST /api/submissions/` with `{"submission_type":"PUBLICATION","doi":"10.1234/example","relevance":"Visual acuity","notes":"Why relevant"}` (illustrative DOI). That existing flow accepts an optional year/contact, deduplicates canonical DOI/source URL across Reference statuses, and writes a private receipt. Discovery does not impersonate a public submitter.
- Each provider/query has a checkpoint. Seven-day date windows progress oldest first; streams alternate to share the request budget. Europe PMC uses `FIRST_IDATE` and cursor pagination. Crossref uses bounded `from-index-date`/`until-index-date`, ascending indexed order and persisted offsets, limited to 10,000. Broad windows exceeding that limit stop explicitly; narrow the query or `window_days`. Offset pagination can move when upstream records are reindexed; overlapping searches reduce this risk but do not guarantee complete coverage. The same-day HTTP cache is reused; the following day refreshes responses. `--offline` only reads that day's cache.
- A page advances only after its records are handled. Mid-page caps preserve its starting position; saved identities make replay idempotent. Invalid records are explicitly retained in JSON reports and mark a run partial. Provider failures retain their checkpoint while other queries continue. Time/request/candidate limits return a partial report; HTTP or invalid-record errors also return a nonzero process exit code. A killed run remains RUNNING until the next applying run marks it INTERRUPTED. The lock is local to this host and database: do not run competing schedulers on different hosts. A distributed worker would need a database-wide lock.
- Exact DOI or source-URL matches against approved, pending and rejected References suppress new inbox records. Existing inbox DOI/provider identities retain their decisions and append evidence. Missing-DOI records retain provider identities; matching titles are possible duplicates, never identity proof. Different DOI versions remain distinct with provider version/type information. A DOI that was entirely absent from a rejected record may require manual reconciliation when later discovered under a different provider identity; the system cannot safely infer that identity from a title alone.
- Europe PMC's `pubYear` is retained at year precision: its generated `firstPublicationDate` can contain padded components. Raw dates remain in evidence. Crossref date parts reuse VPOD's print → online → published/issued policy with separate online/print dates. Candidate metadata is immutable to the runner. Curators edit the linked Reference; acceptance logs field provenance and a private review event, without claiming automatic scientific verification.
- Evidence stores the provider ID, request URL, query rules, category/rationale, retrieval time, provider metadata and run ID. Runs retain the configuration snapshot/hash. No model or prompt runs. External text is stripped/escaped for display; only fixed provider API requests are issued, redirects are refused, and links are validated. Do not add full-text or model tools without revisiting these boundaries.

Provider documentation checked **2026-09-09**: [Europe PMC REST service](https://dev.europepmc.org/RestfulWebService) supports JSON searches, core metadata and cursors. Its literature coverage includes biomedical records and preprints; missing abstracts and indexing delays limit these phrase searches. [Crossref API guidance](https://www.crossref.org/documentation/retrieve-metadata/rest-api/tips-for-using-the-crossref-rest-api/) and [REST API parameters](https://github.com/CrossRef/rest-api-doc) describe bibliographic queries, paging and bounded index-date searches. Crossref covers deposited DOI metadata, often without abstracts. Neither source guarantees exhaustive VPOD coverage. Both public endpoints were queried without keys; the implementation conservatively paces requests at 1.1 seconds, respects Retry-After (long waits defer), uses 5-second connect/20-second read timeouts and at most two retries. `max_requests` bounds HTTP attempts and processed pages; elapsed time is checked between requests. Host process timeout is an additional stop. This pacing is our setting, not a promised provider quota.

Tests use mocked services. Before enabling a wider search, label the pilot relevant/irrelevant/uncertain and compare it with a small manually assembled set of known papers. Record misses and time spent reviewing; tune phrase groups and queue limits to your available curator time. There are no claimed accuracy or cost percentages. Cost is the local process, storage and human review; maintenance includes occasional provider/API changes.

Rollback: stop the timer and set `enabled:false`. Existing public data remains usable. Retain migration 0011's tables to preserve decisions; reversing it deletes discovery history. Restore the database from a reviewed backup only if needed. No database flushing, service restart, or automatic schema change belongs in scheduled execution.
